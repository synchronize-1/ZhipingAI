# 智评校园 - 项目技术文档

> 技术架构、数据库设计、开发规范

## 1. 系统架构

### 1.1 整体架构

```
┌─────────────────────────────────────────────────┐
│              Web 管理前端 (Vue 3)                 │
│   Element Plus + ECharts + Pinia + Vue Router    │
└────────────────────┬────────────────────────────┘
                     │ HTTP / WebSocket
┌────────────────────┴────────────────────────────┐
│              后端 API (Node.js + Express)        │
│                                                  │
│   ┌──────────┐  ┌──────────┐  ┌──────────┐      │
│   │  Routes  │→ │ Services │→ │  Models  │      │
│   │ (路由层)  │  │ (服务层)  │  │ (模型层)  │      │
│   └──────────┘  └──────────┘  └──────────┘      │
│                                                  │
│   Middleware: JWT认证 / 错误处理 / 文件上传       │
└────────────────────┬────────────────────────────┘
                     │
┌────────────────────┴────────────────────────────┐
│              MySQL 8.0+ (43 张表)                │
└─────────────────────────────────────────────────┘
```

### 1.2 后端三层架构

| 层级 | 目录 | 职责 |
|------|------|------|
| Route | `routes/` | 接收请求、参数校验、权限检查、调用 Service |
| Service | `services/` | 业务逻辑编排、多表数据聚合、抛出业务错误 |
| Model | `models/` | 数据库 CRUD、SQL 查询封装 |

**调用链路**：`Route → Service → Model → Database`

### 1.3 统一响应格式

```json
{
  "code": 0,
  "data": {},
  "message": "success"
}
```

| code | 含义 |
|------|------|
| 0 | 成功 |
| 40000 | 参数错误 |
| 40100 | 未认证 |
| 40300 | 权限不足 |
| 40400 | 资源不存在 |
| 50000 | 服务器错误 |


### 3.2 权限控制

路由 meta 配置 `roles` 字段，路由守卫根据 `useUserStore().role` 过滤：

```js
meta: { roles: ['admin', 'teacher'] }
```

三角色权限矩阵：

| 功能 | admin | teacher | student |
|------|:-----:|:-------:|:-------:|
| 考试管理 | 全部 | 自己创建的 | - |
| 成绩导入 | 全部 | 自己班级 | - |
| 成绩查看 | 全部 | 自己班级 | 仅自己 |
| 班级学情分析 | 全部 | 自己班级 | - |
| 学生学情分析 | 全部 | 自己班级 | 仅自己 |
| 班级/学科管理 | 全部 | - | - |
| 成长档案 | 全部 | 自己班级 | 仅自己 |
| 心理健康记录 | 读写 | 读写 | 只读 |
| 评语管理 | 读写 | 读写 | 只读 |

## 5. 开发规范

### 后端

- 新增模块遵循三层架构：Model → Service → Route
- 使用 `utils/response.js` 的 `success/fail/paginate` 返回统一格式
- 使用 `utils/asyncHandler.js` 包装异步路由
- 分页查询使用 `pool.query()` + 内联 LIMIT（不用 `pool.execute` 的 LIMIT 占位符）
- 错误通过 `throw` 抛出，由 `errorHandler` 中间件统一处理

### 前端

- 使用 Composition API + `<script setup>`
- API 调用统一通过 `api/` 层，不直接在组件中写 axios
- 表格页面使用 `useTable` composable 复用逻辑
- 表单弹窗使用 `useDialog` composable 复用逻辑
- 图表使用 ECharts，通过 composable 管理 resize
