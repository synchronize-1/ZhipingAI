# 智评校园 - 项目技术文档

> 技术架构、数据库设计、开发规范

## 1. 系统架构

### 1.1 整体架构

```
┌─────────────────────────────────────────────────┐
│              Web 管理前端 (Vue 3)                 │
│   Element Plus + ECharts + Pinia + Vue Router    │
└────────────────────┬────────────────────────────┘
                     │ HTTP / WebSocket
┌────────────────────┴────────────────────────────┐
│              后端 API (Node.js + Express)        │
│                                                  │
│   ┌──────────┐  ┌──────────┐  ┌──────────┐      │
│   │  Routes  │→ │ Services │→ │  Models  │      │
│   │ (路由层)  │  │ (服务层)  │  │ (模型层)  │      │
│   └──────────┘  └──────────┘  └──────────┘      │
│                                                  │
│   Middleware: JWT认证 / 参数校验 / 错误处理 /      │
│               限流 / 操作审计 / 文件上传           │
│   WebSocket:  Socket.IO（通知推送、食堂人流等）    │
└────────────────────┬────────────────────────────┘
                     │
┌────────────────────┴────────────────────────────┐
│              MySQL 8.0+（51 张表）               │
└─────────────────────────────────────────────────┘
```

### 1.2 后端三层架构

| 层级 | 目录 | 命名 | 职责 |
|------|------|------|------|
| Route | `routes/` | `*.routes.js` | 接收请求、参数校验、权限检查、调用 Service |
| Service | `services/` | `*.service.js` | 业务逻辑编排、多表数据聚合、抛出业务错误 |
| Model | `models/` | `*.model.js` | 数据库 CRUD、SQL 查询封装 |

调用链路：`Route → Service → Model → Database`

### 1.3 统一响应格式

新架构模块统一使用以下信封：

```json
{
  "code": 0,
  "data": {},
  "message": "success"
}
```

| code | 含义 |
|------|------|
| 0 | 成功 |
| 40001 | 参数错误 |
| 40100 | 未认证 |
| 40101 | Token 过期 |
| 40300 | 权限不足 |
| 40400 | 资源不存在 |
| 40900 | 冲突 |
| 50000 | 服务器错误 |

错误码常量定义在 `utils/response.js`。

早期模块（`/api/courses`、`/api/social`、`/api/services`、`/api/ai-health`、`/api/ai-science`）仍使用旧信封：

```json
{ "success": true, "data": {}, "message": "..." }
```

前端 `api/request.js` 的响应拦截器同时兼容两种信封，因此页面代码无需区分。后端统一信封的工作记录在 [项目优化计划](项目优化计划.md) 阶段三。

## 4. 数据库迁移系统

迁移由 `migrations/index.js` 驱动，`migrations/runSql.js` 执行 SQL 文件。每个版本包含一对文件：`V<版本号>_<描述>.up.sql` 与 `V<版本号>_<描述>.down.sql`。执行记录写入 `schema_migrations` 表，重复执行不会重复应用。

```bash
# 执行所有未执行的迁移
npm run migrate

# 查看迁移状态
npm run migrate:status

# 回滚最近一次迁移
npm run migrate:down
```

当前迁移版本：

| 版本 | 内容 |
|------|------|
| `V0.0.1` | 用户表 |
| `V0.0.2` | 基础用户种子 |
| `V1.0.0` | 核心表（班级、学科、考试、成绩、档案、通知已读等） |
| `V1.0.1` | 用户表补充 `class_id` |
| `V1.0.2` | AI 诊断报告表 |
| `V1.0.3` | 课表条目表 |
| `V1.0.4` | 活动报名表 |
| `V1.0.5` | 选修课与选课记录表 |
| `V1.0.6` | 操作日志表 |
| `V1.0.7` | 用户表结构对齐 |
| `V1.0.8` | 通知表增强 |
| `V1.0.9` | AI 健康分析表结构对齐 |

种子数据位于 `migrations/seed/`，均为 SQL 文件，通过 `runSql.js` 执行：`seed_core_data.sql`、`seed_test_users.sql`、`seed_test_scores.sql`、`seed_test_timetable.sql`、`seed_test_activities.sql`、`seed_test_electives.sql`。

种子脚本幂等：以唯一键（如 `users.username`）为准 `ON DUPLICATE KEY UPDATE`，重复执行只补齐或刷新数据。

## 5. 开发规范

### 5.1 文件命名

| 类型 | 规则 | 示例 |
|------|------|------|
| 路由 | `kebab-case.routes.js` | `teaching.routes.js`、`timetable.routes.js` |
| 服务 | `camelCase.service.js` | `teaching.service.js`、`portfolio.service.js` |
| 模型 | `PascalCase.model.js` | `User.model.js`、`TimetableEntry.model.js` |

部分早期文件尚未按此规则改名（如 `routes/course.js`、`routes/social.js`、`routes/auth.js`、`routes/aiHealth.js`、`services/aiScienceService.js`），收敛工作记录在 [项目优化计划](项目优化计划.md) 阶段二。

### 5.2 后端

- 新增模块遵循三层架构：Model → Service → Route
- 使用 `utils/response.js` 的 `success` / `fail` / `paginate` 返回统一格式
- 使用 `utils/asyncHandler.js` 包装异步路由
- 参数校验使用 `middleware/validate.js`，在路由层声明 schema
- 分页查询使用 `pool.query()` + 内联 LIMIT（不用 `pool.execute` 的 LIMIT 占位符）
- 错误通过 `throw` 抛出，由 `errorHandler` 中间件统一处理
- 涉及多表写入的操作使用连接池事务包裹

### 5.3 前端

- 使用 Composition API + `<script setup>`
- API 调用统一通过 `api/` 层，不在组件中直接写 axios
- 表格页面使用 `useTable` composable 复用列表、分页、搜索逻辑
- 表单弹窗使用 `useDialog` composable 复用逻辑
- 图表使用 ECharts，通过 `useECharts` 管理初始化与 resize
